# Latin symbols falling through to Japanese kana glyphs

## Findings and fixes

Cross-reference: Wokann `dev`, `src/text.c` (`RenderText`),
`charmap.txt`, and the native glyph path in JP `asm/text.s`. The native
FC15/FC16 handlers do not select another glyph decoder. The injected Chinese
renderer identifies multi-byte Chinese and 0x7F-prefixed Latin glyphs; ordinary
single-byte characters still use the JP font. Existing normal/small Latin
atlases contain the required symbol bitmaps.

The audit found nine pairs of unescaped parentheses (18 glyph occurrences):

- `Chs_PetalburgWoods_Text_TrainerTipsPP`: two pairs in the PP explanation.
- `Chs_LilycoveCity_ContestLobby_Text_ExplainEMode`: one pair.
- `Chs_LilycoveCity_ContestLobby_Text_ExplainGMode`: three pairs.
- `Chs_LilycoveCity_ContestLobby_Text_ExplainLinkContest`: two pairs.
- `Chs_LilycoveCity_ContestLobby_Text_PlayerAt4PCounterUseGMode`: one pair.

US bytes 0x5C/0x5D map to シ/ス in the JP font. They now use the existing
Latin glyph escape, just like the repaired plus sign. The readable and
US-import encoders also cover equals, semicolon, inverted punctuation,
comparison signs, tilde/middle dot and hyphen, preventing the same problem
when such characters are added later.

Fifteen unescaped hyphens also used the native Japanese long-vowel mark ー:
six in contest explanations/selection labels, two empty move-name table
entries (normal/display), and seven in the empty-ability placeholder. Actual
hyphens now use the Latin font. The empty-ability placeholder intentionally
keeps its existing seven-character Japanese bar in explicit JPN mode; this
also retains the fixed 16-byte ability-name stride. It is not a translated
punctuation string and is excluded by the explicit mode, not by address.

The Cycling Road overflow strings now read 1分钟以上 and 99次以上, matching
native JP 1ぷん いじょう and 99かい いじょう.

## Complete build-text scan

`patch/tools/audit_symbol_glyphs.py` walks the generated text include, tracks
control-code lengths and Chinese/Latin pairs, handles compact resources and
species tokens, and checks each byte vector against the installed ROM. The
layout is checked against linked global symbols. It also checks separately
generated NPC names and handwritten display buffers.

- 15,759 generated text vectors.
- 698 separately generated NPC-name strings.
- Six handwritten ASM/C text buffers; box labels additionally reviewed as
  BOX plus digits only.
- 708,827 generated bytes verified against the ROM (including binary vectors).
- 774 binary Pokedex byte vectors excluded from text interpretation.
- Every unescaped byte in native kana slots 0x01..0xA0 is checked in Chinese
  mode, as are ASCII period/hyphen collisions outside that range.
- Remaining findings: zero. Explicit Japanese player, save and link text is
  preserved, rather than treating legitimate kana as a fault.

This is an audit of build-generated display text and the implemented handwritten
buffers, not a claim that all possible live game states were play-tested.

## Execution validation

`patch/tools/verify_latin_plus.py` compares 14 symbols in both normal and small
fonts against the actual Latin-atlas pixels through the native text renderer.
It checks readable/imported encoders, preservation of explicit Japanese kana,
and native Cycling Road overflow result generation. All pass.

The machine-readable result is `symbol_glyph_audit.json`.
Final ROM CRC32: `68559D33`.
